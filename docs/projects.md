# Projects Tab

Issue [#1199](https://github.com/D-sorganization/Runner_Dashboard/issues/1199) in epic
[#1192](https://github.com/D-sorganization/Runner_Dashboard/issues/1192). One card per fleet
repository: charter feature progress, decisions the board needs to take, and the last
project-steward run on this node. It replaces the per-repo Grok PM bots.

## Contract

| Concern                                                                | Owner                                                                                          | Mechanism                                                                                                                                                                                       |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Charter files (`docs/project/CHARTER.md`, `STATUS.md`, `DECISIONS.md`) | Each repository (templates in Repository_Management `Project_Template/docs/project/`, RM#1679) | Fetched from the default branch through the shared GitHub client (`gh_utils.gh_api`), never cloned                                                                                              |
| Charter parser                                                         | Repository_Management `shared_scripts/project_charter.py` (reference)                          | **Mirrored** in `backend/projects/charter.py`; `tests/api/test_projects_router.py::test_charter_contract_pinned` pins the columns and status vocabulary so the two copies cannot drift silently |
| Steward runs                                                           | Staff Hub (`backend/staff/`)                                                                   | Latest run with `role == "project-steward"` and `repo == <repo>` from the node-local run store                                                                                                  |
| Repo list                                                              | `config/projects.json` (`RUNNER_DASHBOARD_PROJECTS_CONFIG` overrides)                          | Bare names under `GITHUB_ORG`; falls back to the seven fleet repos when the file is missing or malformed                                                                                        |

### Charter contract (mirrored)

- `## End Goal` then `## Non-Goals` open the file, in that order (case-insensitive headings).
- `## Features` holds one markdown table with columns `| ID | Feature | Status | Tracking | Notes |`.
- `Status` is `planned`, `in-progress`, `shipped` or `parked`; `Tracking` is `#123`, `owner/repo#123` or `-`.
- `STATUS.md` is generated: first line `<!-- generated by project-steward; do not hand-edit -->`; the
  bullets under `## Decisions Needed` are what the card lists (the placeholder `None recorded.` is ignored).
- `DECISIONS.md` is an append-only `| Date | Decision | Source (board packet / issue) |` log; the tab does not read it yet.

## Deferred Validation Plans

The packaged configuration includes all ten owners of the twenty external scopes
reviewed under Repository_Management#1687, alongside the existing fleet entries
(thirteen repositories in total; #1251 under #1248). A deployment using
`RUNNER_DASHBOARD_PROJECTS_CONFIG` must include the required owners in that file;
an override remains authoritative. The existing seven-repository fallback is an
availability fallback, not proof of complete deferred-plan coverage.

Each repository owns its planning catalog and charter/status projection. Project
Steward publishes a feature with the original plan ID, `parked` status, `-`
tracking and a durable owner-plan link in Notes. Pending resource, access and
approval decisions belong under `Decisions Needed`; neither a parked feature nor
a generated status is approval or experimental validation. The dashboard reads
these files through its existing parser and reports malformed sources explicitly.
Cards expose each feature ID, name, status, tracking reference and notes under
**Features and plans**. Notes support basic inline Markdown and HTTP(S) links;
executable URLs and HTML are removed before rendering.

#1248 and Repository_Management#1687 retain end-to-end rollout acceptance: publish
owner files, deploy the reviewed configuration, allow the ten-minute cache to
refresh, then verify all twenty real IDs/links, parked states and pending decisions
in the live API and UI. Passing the synthetic API fixture proves projection
behavior only. Restore the prior configuration to roll back this additive owner
list; no plan or source issue is deleted by a configuration change.

## API (`/api/projects`)

| Method | Path                   | Auth       | Purpose                                                                  |
| ------ | ---------------------- | ---------- | ------------------------------------------------------------------------ |
| GET    | `/api/projects`        | fleet peer | Every configured repository, in config order, cached 10 minutes per repo |
| GET    | `/api/projects/{repo}` | fleet peer | One configured repository; `404` when the name is not in the config      |

Per repository:

```json
{
  "repo": "UpstreamDrift",
  "charter_present": true,
  "features": [
    {
      "id": "F1",
      "feature": "...",
      "status": "shipped",
      "tracking": "#123",
      "notes": ""
    }
  ],
  "progress": {
    "planned": 2,
    "in_progress": 1,
    "shipped": 4,
    "parked": 0,
    "percent_shipped": 57
  },
  "status_present": true,
  "decisions_needed": ["Retire the legacy solver?"],
  "last_steward_run": {
    "id": "...",
    "status": "succeeded",
    "created_at": "...",
    "ended_at": "..."
  },
  "error": "charter invalid: Feature F3: invalid status 'someday'"
}
```

`charter_present: false` means `docs/project/CHARTER.md` is absent on the default branch. A malformed
charter keeps `charter_present: true` with empty `features` and the reason in `error`; a GitHub failure
lands in `error` too. The list route never answers 5xx because of one repository (orthogonality). The
cached overview is refreshed every `cache_ttl_seconds`; `last_steward_run` is re-read from the local store
on every call.

## Frontend

`frontend/src/pages/ProjectsPage.tsx` (+ `pages/Projects/`), nav id `projects` in the **AI & Agents**
group. Each card shows the stacked shipped / in-progress / planned / parked bar, the decisions-needed
list and the last steward run (linked to `/api/staff/runs/{id}` until the Staff tab, #1198, lands).
**Run steward now** posts `{"repo": "<repo>", "prompt": "Scheduled steward pass", "machine": "auto"}`
to `POST /api/staff/project-steward/run` through `apiRequest` (CSRF header included); the response or
error is shown on the card. The role itself is defined in Repository_Management `staff/roles/project-steward.yml`
(RM#1677) and must be present in `STAFF_ROLES_DIR` for the dispatch to succeed.
